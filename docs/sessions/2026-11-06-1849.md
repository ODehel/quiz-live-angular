## Leçons de méthode

- **Un smoke test doit contrôler l'état hors dépôt avant d'agir, la leçon du 2026-11-04 n'a pas été appliquée.** `smoke-routing.ps1` faisait un `POST` du token avant toute modification. `smoke-fix-error.ps1` ne le faisait pas : le scénario « mauvais mot de passe » est devenu non discriminant, et le scénario « bon mot de passe » a fini en 401 sans explication jusqu'à une sonde faite après coup. Repartir de `smoke-routing.ps1` pour le prochain script.
- **Valider un script sous PowerShell 7.5 Linux ne valide pas Windows PowerShell 5.1.** Trois itérations ont été nécessaires : `2>&1` sous `$ErrorActionPreference = 'Stop'` (hypothèse, jamais isolée), UTF-8 sans BOM (accents corrompus dans la transcription), détection de port faussement négative alors que `ng serve` répondait (corrigée par un test IPv4 et IPv6, un test HTTP et la ligne `Local:` du journal ; l'effet est confirmé, le mécanisme IPv6 ne l'est pas).
- **Un échec de script doit atteindre la transcription.** Un `throw` seul disparaissait : `catch` avec `Write-Output "ECHEC : …"`, et journal du processus lancé affiché en cas de timeout.
- **Un scénario négatif ne se prouve que si la ligne de base est positive.** Sinon « toujours en erreur » ne distingue pas le correctif d'une panne préexistante.
- **L'audit de `clearError` avant la porte 1 a tenu** : un seul appel de production, donc l'option B n'a pas gonflé. Le choix laissé ouvert par la décision #12 est levé par la décision #13.
- **Outils** : `pkill -f "ng serve"` tue son propre shell dès que la ligne de commande contient le motif (sortie 144, vu deux fois) → `[n]g serve` et jamais le mot dans une commande qui lance le script. `gh pr create` échoue en session (GraphQL interdit) → `gh api repos/ODehel/quiz-live-angular/pulls`. `session-open.ps1` et `session-close.ps1` ne tournent pas hors Windows (`npx.cmd`) : à lancer par Olivier, ou à rendre portables.
