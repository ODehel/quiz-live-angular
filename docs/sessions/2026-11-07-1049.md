## Leçons de méthode

- **Vérifier l'hypothèse sur le réel avant de cadrer.** « Probable » est devenu « constaté » en dix secondes (Node 22, `WebSocket` natif). Le cadrage est parti d'un fait, pas d'une intuition.
- **Une cellule ✅ de la matrice peut reposer sur un double.** CA-7 était marqué ✅ alors que le service n'avait jamais envoyé le message sur une vraie socket : le faux acceptait ce que le vrai refuse. La note de CA-7 le dit maintenant.
- **Un test né vert se mute.** Le moment de lecture du token n'avait pas de rouge naturel (l'implémentation le faisait déjà) ; la mutation « lecture à la construction » a rendu le test rouge. Le test « token courant à la reconnexion » seul ne l'aurait pas attrapée, car le second socket est construit après le changement de token.
- **Adapter des tests existants n'est pas les affaiblir.** Quatre tests ont reçu `simulateOpen()` parce que le comportement spécifié a changé ; aucune assertion n'a été modifiée.
- **Commit `fix`, pas `chore`.** Choix d'Olivier : c'est une correction. Contrairement à `refresh()`, le défaut existait dans le code livré, même sans appelant en production.
- **Rien à refactorer.** Quatre lignes de production, aucune duplication : le refactor est vide et c'est dit.
