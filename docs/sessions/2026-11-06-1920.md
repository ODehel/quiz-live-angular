## Leçons de méthode

- **Un test né vert doit être détecté avant d'être gardé.** La ligne mise à jour du test paramétré passait avec l'ancien texte. Seul un test d'absence discriminait. Réflexe : lancer le test modifié sur l'ancien code avant de l'appeler « rouge ».
- **Écrire un script de smoke test sans pouvoir l'exécuter coûte des allers-retours.** Trois lancements (deux échecs du script, un vert), tous deux sans rapport avec le code : `ReadAllText` sur un journal encore ouvert en écriture par `ng serve` (verrou), puis détection de port : `TcpClient` est IPv4 par défaut et ne peut pas joindre `::1`. Piège déjà noté au récap précédent, corrigé à moitié la première fois. Le script v3 (jointe aux échanges, hors dépôt) est celui à reprendre : lecture avec `FileShare.ReadWrite`, trois signaux de démarrage indépendants, famille d'adresse du client alignée sur l'adresse.
- **Mécanisme du faux négatif de port non élucidé.** Au run vert : `http=True port=False log=False` au premier sondage. L'effet est contourné (le HTTP suffit), mais pourquoi `port=False` malgré le correctif de famille, et `log=False` à ce sondage (journal pas encore vidé ?), n'a pas été isolé.
- **Un relevé par `grep` doit être relu avant d'être cru.** Mes options (`--include`, `--exclude`) placées après `--` ont donné des comptes faux (erreurs de `grep` comptées comme sorties) : relevé refait, comptes identiques au précédent.
- **Contrôle d'état avant d'agir, appliqué cette fois.** Le script vérifie hub éteint et port 4200 libre avant de lancer, et pose trois contrôles positifs avant la cible : la leçon du 2026-11-04 et du handoff précédent a tenu.
- **Le hook « Stop » a signalé deux fois un commit non poussé à tort.** La branche distante existait (`ls-remote`) et son sommet égalait le `HEAD` ; le clone superficiel n'avait pas de référence de suivi `origin/<branche>`. Recréée par un fetch avec refspec explicite, configuration de suivi posée à la main, rien repoussé.
- **Outils** : `gh pr create` échoue en session → `gh api repos/ODehel/quiz-live-angular/pulls`. `session-open.ps1` et `session-close.ps1` ne tournent pas hors Windows (`npx.cmd`) : handoff écrit à la main, comme la session précédente.
