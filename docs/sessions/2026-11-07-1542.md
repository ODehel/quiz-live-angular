## Leçons de méthode

- **Le compilateur a servi de premier smoke test.** Brancher le service sur le vrai `WebSocket` a immédiatement montré que `SocketLike.onopen` avait été dessiné d'après la doublure, pas d'après le natif. Un contrat écrit seulement contre un faux ment sans que personne le voie.
- **Une valeur « neutre » doit rester valide.** `set-by-ci` n'est pas une URL : `new WebSocket` aurait levé `SyntaxError` au démarrage en production. Écart signalé à la porte 1 et tranché (`wss://set-by-ci.invalid/ws`).
- **Isoler le rouge dans un fichier neuf.** Le rouge d'import de R1 n'a ainsi pas masqué les 10 tests existants de `app.config.spec.ts`.
- **Un test de garde est un vrai rouge.** R2 (« pas de socket si le token échoue ») a forcé `isReady()` : `initialize()` avale l'erreur, donc `await initialize(); connect()` seul aurait connecté sans token.
- **Le log du hub ne prouve pas tout.** Il établit l'ordre des requêtes (token avant socket, pas de nouveau token à la reprise) ; la trame `auth_success` côté navigateur n'est visible que dans DevTools.
- **Dire ce qui est déduit.** Les délais du backoff sont cohérents avec l'horodatage, pas mesurés : le handoff le dit.
- **Limites d'environnement.** `ng build` bloqué (polices) et `gh pr create` bloqué (GraphQL, PR ouverte par l'API REST).
