## Décision
Aucune décision de conception : pas d'entrée dans `docs/decisions/DECISIONS.md`. Choix non observables, à challenger en revue :
- **`serverClose()` sur `ClosingFakeSocket`, comme validé** : elle délègue à `simulateClose()` (qui existe déjà sur `FakeSocket` et fait la même chose) ; ce n'est qu'un alias qui nomme l'intention (voir la dette). Variante écartée : réutiliser `simulateClose(4002)` sans nouvelle méthode (même preuve, une méthode de moins).
- **`hubClosesWith()` plutôt qu'un cast ou un type de retour générique des aides** : `startAndOpenSocket()` et `startAndAnnounce*()` rendent un `FakeSocket` ; la garde `instanceof` évite de toucher à `app.config.test-helpers.ts` et protège l'ordre de la surcharge.
- **`it.each` de CA-33 entièrement passés sur `ClosingFakeSocket`**, 1000, 1006 et 4004 compris : changer la doublure pour le seul `4002` aurait demandé une branche dans le test ou un second test de même titre. Le comportement testé de ces trois codes est identique (même `onclose`).
- **Pas de test ajouté** : les titres existants disent déjà la chaîne `token_expired` → `4002` → un `refresh()` → une reconnexion avec le nouveau token ; assertions déjà présentes (un seul `POST` via `expectOne`, `expectNone` ensuite, 1 socket puis 2, `auth` avec `fresh-jwt`, rien rouvert pendant 5 s sans token).
- **Pas touché** : `FakeSocket`, les tests du `1000` (hors un commentaire devenu faux), du `4004`, `app.config.test-helpers.ts`.
